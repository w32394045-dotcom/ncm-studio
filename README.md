# NCM Studio

网易云音乐 `.ncm` 解密工具，Go 单文件二进制，自带网页界面。

解密音频的同时会把歌词抓下来、**直接写进音乐文件本身**（FLAC 写 Vorbis comment，
MP3 写 ID3v2），并可选生成同名 `.lrc`。

## 编译

```bash
go build -ldflags "-X main.buildVersion=1.0.0" -o ncmstudio .
```

交叉编译到手机（在电脑上执行）：

```bash
GOOS=android GOARCH=arm64 CGO_ENABLED=0 \
  go build -ldflags "-X main.buildVersion=1.0.0" -o ncmstudio .
```

## 运行

```bash
./ncmstudio                       # 扫描 home，输出到 ~/ncm-output
./ncmstudio -dir /sdcard/Music -output /sdcard/Music/mp3
./ncmstudio -workers 4 -lyrics both
./ncmstudio -version
```

打开 <http://127.0.0.1:8080> 即可使用。

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `-host` | `127.0.0.1` | 监听地址；改成 `0.0.0.0` 才会对局域网开放 |
| `-port` | `8080` | 监听端口 |
| `-dir` | home | 扫描 `.ncm` 的目录 |
| `-output` | `<dir>/ncm-output` | 解密输出目录 |
| `-workers` | `3` | 并发解码文件数量：1 就是一次只解码一个 ncm，2 就是两个，以此类推；只在 1–16 之间取值 |
| `-lyrics` | `both` | `off` / `embed` / `both` |
| `-workspace` | 程序所在目录 | 封面库和歌词缓存的存放位置 |
| `-config` | 系统配置目录 | 设置文件的存放位置 |

设置会持久化：在网页「设置」里改过之后，下次启动直接沿用。
但**显式写在命令行上的参数每次都优先**于保存的设置——只有没写的那几项才读存档，
所以命令行不会被一个过期的配置文件悄悄盖掉。

## 三个目录

第一次打开会先问三个目录，之后各管各的，随时能在首页或设置里改：

| | 作用 | 默认 |
| --- | --- | --- |
| 扫描目录 | `.ncm` 放在哪 | home |
| 输出目录 | 解密后的音乐写到哪 | `<扫描目录>/ncm-output` |
| 运行目录 | 封面库、歌词缓存放哪 | 程序所在目录 |

运行目录改完立刻生效，不用重启——封面库和歌词缓存都会跟着搬过去。

## 网页界面

八个标签页：

- **转换** — 最上面是三个目录的卡片，点一下就能换。选目录、扫描、勾选、开始，
  进度通过 SSE 实时推送逐条更新，可随时停止。支持把 `.ncm` 直接拖到页面上上传。
  运行栏上的步进器可以直接调并发解码文件数量，改完立刻生效。
- **补歌词** — 已经解密好的音频补歌词：用标签和文件名去网易云搜索，匹配确定后写进文件。
- **歌詞檔案** — 在标签里的歌词和同名 `.lrc` 之间来回导入导出。
- **AI 翻譯** — 用模型翻译歌词，再写回文件。
- **封面** — 逐个文件看封面、换封面，或按名称补全缺失的封面（见下）。
- **文件** — 浏览磁盘，重命名、删除、下载，或把某个目录设为扫描源。
- **资讯** — 每个文件的平台 ID、格式、码率、时长、有没有歌词和封面。
- **设置** — 三个目录、并发解码文件数量、歌词模式、界面语言（简中 / 繁中 / 英 / 日 / 韩）、
  扫描大小过滤（见下）。

已经解密过的文件会按内容指纹自动跳过；把输出文件删掉，它就会重新排队。

## 扫描大小过滤

设置里有一项「扫描大小过滤（小于）」：一个数字加一个单位下拉（KB / MB / GB），
默认 **500 KB**。

- 比这个值小的文件不会进入转换队列，也不会被勾选；留空或填 `0` 就是不过滤。
- 过滤**不会把文件藏起来**：列表里那一行还在，只是标成「小于 500 KB」并且不能勾选。
  直接消失更省事，但那样文件夹里少了什么就没人看得懂了。
- 改完马上重新扫描当前页面，不用手动再扫一次。
- 存的永远是字节数，单位只是显示方式；所以把下拉从 KB 切成 MB，这条线不会偷偷移动，
  页面上写着多少就是多少。
- 这个过滤同时管转换列表、补歌词、封面、歌詞檔案和资讯页——它们用的是同一份设置。

## 封面

列表里每个音频文件旁边都有一个图片按钮，点开就是封面编辑器。分三块：

- **真·原始封面** — 第一次打开这个文件时它自带的封面，一直留着，不能删。
- **网易云官方封面** — 用文件里的 `musicId` 去拉的原图，通常比文件自带的那张清楚。
- **历史封面** — 换掉的那些自动存一份，点一下就能换回来，也能删。

换封面只重写标签块，音频数据一个字节都不动，所以一百多兆的文件也是秒切。
封面库按**音频指纹**（前 256 KiB 音频的 sha256）索引而不是按路径，
改名、搬家都不会丢；文件删了封面还在库里。

改完封面之后：

- **列表里那一个文件的缩略图立刻更新**，不用重新扫描、也不用刷新页面。实现上就是给
  那张图的 URL 加一个只属于这个文件的版本号（其余行的 URL 一个字符都没变，不会重下），
  加上服务端给「当前封面」发了 ETag，所以刷新页面时也是 304 而不是把几百张图重下一遍。
- 编辑器打开着、请求还没回来时页面被重绘（比如切语言），也不会再崩在空数据上。

### 按名称补全封面

封面页工具栏上的「按名称补全封面」是歌词补全的封面版：列表里**没有封面**的文件，
用它的标签去网易云搜索，标签什么都没有的时候就用**文件名**解析出的「歌手 - 标题」去搜，
匹配确定后把官方封面（1024×1024 那张）写进文件。

- 一次一个文件，可以随时「停止」；每个文件只重写标签块。
- 已经有封面的文件不动——那是别人自己选的图，静默替换是这里唯一无法撤销的操作。
- 匹配不确定的文件不写，标成「待确认」，把原因写在行上（和补歌词同一套判定）。
- 文件太小（低于上面的扫描大小过滤）的文件直接拒绝，不给它写任何东西。

## 歌词

`.ncm` 里**没有**歌词，只有歌曲 ID（`musicId`）。所以解密时用这个 ID 去请求
网易云公开接口：

```
https://music.163.com/api/song/lyric?id=<musicId>&lv=-1&kv=-1&tv=-1&rv=-1
```

不需要登录。拿到 `lrc.lyric`（原文）和 `tlyric.lyric`（翻译）后按下表写入。

| `-lyrics` | 行为 |
| --- | --- |
| `off` | 不抓歌词，只解密 |
| `embed` | 只写进音频标签 |
| `both` | 标签 + 同名 `.lrc` 文件（默认） |

写进文件的字段：

- `LYRICS` — 双语合并（原文 + 翻译交错），播放器直接显示这一条
- `UNSYNCEDLYRICS` / `USLT` — 同上，兼容只认这个字段的播放器
- `LYRICS_ORIGINAL` — 纯原文
- `LYRICS_TRANSLATION` — 纯翻译

接口返回「暂无歌词」或 `uncollected` 时，跳过并在界面上标为 `none`，不算失败；
网络错误标为 `failed`，音频照常输出，只是没有歌词。

## 说明

- 默认只绑 `127.0.0.1`，没有登录也没有多用户——它是给自己用的本地工具。
- 内核只做解密，不上传任何东西；除歌词和封面接口外不发起网络请求。
- 输出文件先写 `.part` 再改名，中途中断不会留下一个看起来完整的坏文件。
- 换封面同样是先写 `.part` 再改名，所以中途断电也不会毁掉原文件。
- 并发解码文件数量越大越快，但每一份并发都要占一份解密缓冲、一个文件句柄和一份 CPU；
  手机上 2–4 足够，再往上多半是让手机发烫而不是更快。改动立刻生效，不用重启。
